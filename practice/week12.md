# Week 12 실습

## 오늘 실행해본 코드 중 가장 흥미로웠던 것

이번 12주차 실습에서는 **프로시저럴 생성**을 주제로 세 가지 코드를 실행해 보았다. 오늘 실습 순서는 `bsp_dungeon.py`, `cellular_cave.py`, `perlin_terrain.py`를 직접 실행해 보고, 각 코드의 파라미터를 바꿔 보면서 결과가 어떻게 달라지는지 확인하는 방식이었다. 수업 자료에서도 코드를 완벽하게 이해하지 못해도 괜찮고, 직접 실행하면서 파라미터를 바꿔 보는 것이 목표라고 되어 있어서 부담 없이 결과 변화를 관찰하는 데 집중했다.

세 가지 코드 중에서 가장 흥미로웠던 것은 **BSP 던전 생성 코드인 `bsp_dungeon.py`**였다. 이 코드는 단순히 랜덤하게 방을 찍어내는 것이 아니라, 하나의 큰 공간을 여러 구역으로 나누고, 그 안에 방을 배치한 뒤, 방과 방을 통로로 연결하는 방식이었다. 실행해 보면서 `SPACE` 키를 누르면 한 단계씩 진행되고, `A` 키를 누르면 자동으로 진행되며, `F` 키로 현재 단계를 건너뛰고, `N` 키로 새로운 seed를 적용해 처음부터 다시 생성할 수 있었다.

특히 흥미로웠던 점은 던전이 한 번에 완성되는 것이 아니라 **공간 분할 → 방 배치 → 통로 연결 → MST 정리**의 흐름으로 점점 만들어진다는 점이었다. 처음에는 큰 사각형 공간이 나뉘는 모습만 보이지만, 이후 각 공간 안에 방이 생기고, 방 사이가 통로로 연결되면서 실제 게임 던전처럼 보이는 구조가 만들어졌다. 이 과정을 단계별로 보니, 게임에서 던전이 무작위로 생성된다고 해서 아무렇게나 만들어지는 것이 아니라 일정한 규칙과 알고리즘을 통해 플레이 가능한 구조로 만들어진다는 것을 알 수 있었다.

또한 `N` 키를 눌러 seed를 바꾸면 완전히 다른 던전이 생성되는 점도 인상 깊었다. 같은 코드와 같은 규칙을 사용하더라도 seed 값이 달라지면 방의 위치, 공간 분할 방식, 통로 모양이 달라졌다. 이를 보면서 프로시저럴 생성은 단순한 랜덤이 아니라, 규칙 안에서 다양한 결과물을 만들어내는 방식이라는 생각이 들었다. 게임 개발에서 매번 다른 맵을 만들거나, 플레이어가 반복해서 플레이해도 지루하지 않게 만드는 데 매우 유용할 것 같았다.

`cellular_cave.py`도 흥미로웠다. 이 코드는 초기 랜덤 상태가 반복을 거치면서 점점 동굴처럼 자연스러운 형태로 변하는 과정을 보여 주었다. 처음에는 벽과 빈 공간이 무작위로 흩어져 있는 것처럼 보였지만, 여러 번 반복되면서 뭉쳐야 할 부분은 뭉치고 비워질 부분은 비워지면서 동굴 형태에 가까워졌다. 이 방식은 인위적인 방 구조보다 자연스럽고 불규칙한 지형을 만들 때 어울린다고 느꼈다.

`perlin_terrain.py`는 Perlin Noise를 이용해 지형을 만드는 코드였다. 실행 전에 `pip install noise`로 라이브러리를 설치해야 했고, 실행 후에는 `N` 키로 새로운 seed를 적용하고, 위아래 방향키로 `scale` 값을 조절하며, 좌우 방향키로 지형을 이동하고, `SPACE` 키로 일시정지할 수 있었다. 이 코드는 던전이나 동굴보다 지형의 높낮이 변화를 직접 확인할 수 있어서, 횡스크롤 게임의 산, 언덕, 지형 생성에 잘 어울릴 것 같았다.

전체적으로 세 가지 코드 모두 랜덤 요소를 활용하지만 결과물의 느낌은 서로 달랐다. BSP는 방과 통로가 있는 던전 구조에 적합했고, Cellular Automata는 자연스러운 동굴 구조에 적합했으며, Perlin Noise는 부드럽거나 험준한 지형을 만드는 데 적합했다. 그중에서도 나는 게임 맵이 만들어지는 과정이 단계별로 잘 보이는 BSP 던전 생성이 가장 흥미로웠다. 결과만 보는 것이 아니라 생성 과정을 볼 수 있어서 알고리즘이 실제 게임 구조로 이어지는 느낌을 가장 잘 이해할 수 있었기 때문이다.

## 파라미터를 바꿨을 때 어떤 변화가 있었는지

이번 실습에서 중요한 부분은 코드를 단순히 실행하는 것이 아니라, **파라미터를 바꿨을 때 결과가 어떻게 달라지는지 확인하는 것**이었다. 프로시저럴 생성은 정해진 결과물을 직접 하나하나 배치하는 것이 아니라, 규칙과 값에 따라 결과가 자동으로 만들어지는 방식이기 때문에 파라미터 변화가 결과에 큰 영향을 준다는 것을 알 수 있었다.

먼저 `bsp_dungeon.py`에서는 seed를 바꾸는 것이 가장 눈에 띄는 변화였다. `N` 키를 눌러 새로운 seed로 다시 시작하면 던전의 전체 구조가 바뀌었다. 방의 위치가 달라지고, 공간이 나뉘는 방식도 달라졌으며, 통로 연결 모양도 새롭게 만들어졌다. 하지만 완전히 아무렇게나 만들어지는 것은 아니었다. 공간을 분할하고, 방을 만들고, 통로로 연결한다는 기본 규칙은 유지되었다. 이 점에서 seed는 결과의 다양성을 만드는 역할을 하고, 알고리즘은 결과가 던전처럼 보이도록 형태를 잡아 주는 역할을 한다고 느꼈다.

`cellular_cave.py`에서는 코드 상단의 `FILL_PROB`와 `ITERATIONS` 값을 바꿔 보는 것이 핵심이었다. `FILL_PROB`는 처음에 벽이 얼마나 많이 채워질지를 결정하는 값이라고 이해했다. 이 값이 높아지면 처음부터 벽이 많은 상태로 시작하기 때문에 전체적으로 막힌 부분이 많고 좁은 동굴이 만들어질 가능성이 커진다. 반대로 값이 낮아지면 빈 공간이 많아져 넓고 뚫린 구조가 만들어질 수 있다.

`ITERATIONS` 값은 초기 랜덤 상태를 몇 번 반복해서 정리할지에 영향을 주는 값이라고 느꼈다. 반복 횟수가 적으면 처음의 무작위 느낌이 많이 남아 있어서 거칠고 불안정한 형태가 보인다. 반대로 반복 횟수가 많아지면 작은 노이즈가 줄어들고, 벽과 빈 공간이 더 자연스럽게 정리된다. 하지만 너무 많이 반복하면 지형이 지나치게 단순해질 수도 있을 것 같았다. 따라서 동굴을 만들 때는 `FILL_PROB`와 `ITERATIONS`를 적절히 조절해서 너무 막히지도 않고, 너무 비어 있지도 않은 구조를 만드는 것이 중요하다고 생각했다.

`perlin_terrain.py`에서는 `scale` 값의 변화가 가장 직접적으로 보였다. 수업 자료에서도 `scale` 값이 작을수록 완만한 지형이 되고, 클수록 험준한 지형이 된다고 설명되어 있었다. 실제로 `scale`이 작을 때는 지형의 높낮이 변화가 부드럽고 천천히 이어지는 느낌이 강했다. 이런 지형은 이동하기 편한 필드나 평화로운 배경에 어울릴 것 같았다. 반대로 `scale` 값을 키우면 높낮이 변화가 더 자주 나타나고, 지형이 거칠고 험준해지는 느낌이 들었다. 이런 형태는 산악 지형, 위험 지역, 난이도가 높은 맵에 사용할 수 있을 것 같았다.

또한 `perlin_terrain.py`의 코드 상단에 있는 `OCTAVES` 값을 바꾸면 지형의 세부적인 변화가 달라질 수 있다는 점도 배웠다. `OCTAVES`는 지형의 노이즈를 얼마나 여러 층으로 쌓을지와 관련된 값으로 이해했다. 이 값이 바뀌면 단순한 곡선 형태에서 더 복잡하고 세밀한 지형으로 변할 수 있다. 다만 너무 복잡하게 만들면 플레이어가 이동하기 불편한 지형이 될 수도 있기 때문에, 게임 장르에 맞는 적절한 값 조절이 필요하다고 느꼈다.

이번 실습을 통해 파라미터는 단순한 숫자가 아니라 게임의 분위기와 플레이 경험을 바꾸는 중요한 요소라는 것을 알게 되었다. 같은 알고리즘을 사용하더라도 어떤 값을 넣느냐에 따라 결과가 완전히 달라질 수 있다. 그래서 프로시저럴 생성을 사용할 때는 무작정 랜덤하게 만드는 것이 아니라, 원하는 게임 분위기와 플레이 목적에 맞게 파라미터를 조절해야 한다고 생각했다.

## 기말 프로젝트에서 프로시저럴 생성을 활용할 수 있을지

기말 프로젝트에서 프로시저럴 생성을 활용할 수 있을지 생각해 보았을 때, 충분히 활용 가능성이 있다고 느꼈다. 특히 게임 프로젝트에서는 맵, 지형, 방 배치, 아이템 위치, 적 등장 위치 등 반복해서 만들기 번거로운 요소가 많기 때문에 프로시저럴 생성이 큰 도움이 될 수 있다고 생각했다.

먼저 BSP 던전 생성 방식은 **던전형 맵이나 방 기반 구조**를 만들 때 활용할 수 있을 것 같다. 예를 들어 탑을 오르거나 던전을 탐험하는 게임을 만든다면, 매번 같은 구조가 아니라 seed에 따라 다른 방 배치와 통로를 가진 맵을 만들 수 있다. 플레이어는 같은 게임을 다시 플레이하더라도 새로운 구조를 만나게 되기 때문에 반복 플레이의 재미가 늘어날 수 있다. 또한 방과 통로가 규칙적으로 연결되기 때문에 완전히 무작위로 배치하는 것보다 플레이 가능한 맵을 만들기 쉽다는 장점이 있다.

Cellular Automata 방식은 **동굴, 폐허, 지하 공간, 자연 지형**을 만들 때 어울린다고 느꼈다. BSP가 비교적 인공적인 방과 복도 구조라면, Cellular Automata는 불규칙하고 자연스러운 형태를 만들 수 있다. 기말 프로젝트에서 어두운 동굴이나 지하 감옥 같은 분위기의 맵이 필요하다면 이 방식을 활용해 자연스럽게 뚫린 공간과 막힌 공간을 만들 수 있을 것 같다. 특히 `FILL_PROB`와 `ITERATIONS`를 조절하면 좁고 답답한 동굴부터 넓은 공동이 많은 동굴까지 다양하게 만들 수 있을 것 같다.

Perlin Noise는 **횡스크롤 지형이나 배경 지형 생성**에 활용할 수 있을 것 같다. 예를 들어 2D 게임에서 언덕, 산, 지면의 높낮이를 만들 때 매번 직접 그리는 대신 Perlin Noise를 이용하면 자연스러운 지형을 생성할 수 있다. `scale` 값을 조절해 평탄한 길, 험준한 산길, 굴곡이 많은 지역을 구분할 수도 있을 것 같다. 또한 배경의 산맥이나 먼 지형 실루엣을 자동으로 만드는 데도 응용할 수 있을 것 같았다.

하지만 기말 프로젝트에 프로시저럴 생성을 바로 적용하려면 주의할 점도 있다고 생각했다. 첫째, 랜덤으로 만들어진 결과가 항상 좋은 것은 아니기 때문에, 플레이어가 이동할 수 없는 구조가 생기지 않도록 검사를 해야 한다. 둘째, 너무 랜덤성이 강하면 게임의 난이도나 흐름이 불안정해질 수 있다. 셋째, 프로젝트 기간이 제한되어 있다면 알고리즘을 완벽하게 새로 만드는 것보다, 수업에서 제공된 코드를 참고해 필요한 부분만 간단히 응용하는 것이 현실적일 것 같다.

기말 프로젝트에서 내가 활용한다면, 전체 게임 맵을 완전히 랜덤으로 만들기보다는 일부 요소에만 프로시저럴 생성을 적용하는 방식이 좋을 것 같다. 예를 들어 방의 기본 구조는 직접 만들고, 아이템 위치나 장애물 위치를 랜덤하게 바꾸거나, 배경 지형의 일부를 Perlin Noise로 생성하는 방식이 부담이 적을 것 같다. 이렇게 하면 프로젝트의 안정성은 유지하면서도 매번 조금씩 다른 플레이 경험을 줄 수 있다.

이번 실습을 통해 프로시저럴 생성은 단순히 랜덤한 결과를 만드는 기술이 아니라, 규칙과 파라미터를 이용해 다양한 콘텐츠를 자동으로 만드는 방법이라는 것을 알게 되었다. 기말 프로젝트에서 반드시 복잡하게 사용하지 않더라도, seed, scale, 반복 횟수 같은 개념을 이해하고 있으면 게임의 반복성이나 다양성을 높이는 데 도움이 될 것 같다. 앞으로 프로젝트를 만들 때 직접 배치해야 하는 요소와 자동으로 생성할 수 있는 요소를 구분해서 생각해 보면 더 효율적으로 개발할 수 있을 것 같다.

## 학습성찰

이번 12주차 실습은 프로시저럴 생성이라는 개념을 실제 코드로 확인해 보는 시간이었다. 처음에는 프로시저럴 생성이 단순히 랜덤으로 맵을 만드는 것이라고 생각했는데, 실습을 해 보면서 단순한 랜덤과는 다르다는 것을 알게 되었다. BSP 던전 생성, Cellular Automata 동굴 생성, Perlin Noise 지형 생성은 모두 랜덤 요소를 사용하지만, 각각의 알고리즘이 가진 규칙에 따라 결과물이 일정한 형태와 목적을 가지게 된다.

가장 크게 느낀 점은 **게임에서 랜덤성은 규칙 없이 아무렇게나 만드는 것이 아니라, 플레이 가능한 결과를 만들기 위해 조절되어야 한다는 것**이다. 던전은 방과 통로가 연결되어야 하고, 동굴은 너무 막히거나 너무 비어 있으면 안 되며, 지형은 플레이어가 이동할 수 있을 정도로 적절한 높낮이를 가져야 한다. 즉, 프로시저럴 생성은 자동으로 콘텐츠를 만드는 기술이지만, 그 결과가 게임에 적합한지 판단하고 조절하는 개발자의 역할도 중요하다고 느꼈다.

또한 파라미터를 바꾸는 과정이 생각보다 중요하다는 것을 알게 되었다. `FILL_PROB`, `ITERATIONS`, `scale`, `OCTAVES` 같은 값은 코드 안에 있는 단순한 숫자처럼 보이지만, 실제로는 결과물의 형태와 분위기를 크게 바꾼다. 이 값을 조절하면서 결과를 확인하는 과정은 게임의 밸런스를 맞추는 작업과 비슷하다고 느꼈다. 앞으로 코드를 작성할 때도 숫자를 아무렇게나 넣기보다는, 값이 결과에 어떤 영향을 주는지 확인하면서 조정해야겠다고 생각했다.

이번 실습은 코드를 완벽히 이해하지 못해도 직접 실행하고 관찰하는 것만으로 많은 것을 배울 수 있다는 점에서도 의미가 있었다. 알고리즘 내부 구조를 모두 설명할 수는 없더라도, 어떤 입력값을 바꾸면 어떤 결과가 나오는지 확인하는 과정은 실제 개발에서 매우 중요하다고 느꼈다. 특히 게임 개발에서는 눈으로 결과를 확인하고 수정하는 과정이 많기 때문에, 실행 결과를 관찰하고 개선하는 습관이 필요하다고 생각했다.

기말 프로젝트를 진행할 때도 이번 실습 내용을 참고할 수 있을 것 같다. 프로젝트의 규모가 크지 않더라도, 맵 일부나 배경, 장애물 배치, 아이템 위치 등에 프로시저럴 생성 개념을 적용하면 더 다양한 결과를 만들 수 있을 것 같다. 다만 무리하게 복잡한 알고리즘을 넣기보다는, 프로젝트 완성도를 해치지 않는 범위에서 간단하게 활용하는 것이 좋겠다고 느꼈다.

정리하면, 이번 12주차 수업을 통해 프로시저럴 생성의 기본적인 활용 방식과 파라미터 조절의 중요성을 배웠다. BSP 던전 생성은 구조적인 던전 제작에, Cellular Automata는 자연스러운 동굴 생성에, Perlin Noise는 지형 생성에 적합하다는 것을 알게 되었다. 앞으로 게임을 만들 때 모든 요소를 직접 배치하는 방식만 생각하지 않고, 규칙을 설계해서 자동으로 다양성을 만드는 방식도 함께 고민해 봐야겠다고 느꼈다.
