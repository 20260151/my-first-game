# 4주차 실습 정리

## 오늘 한 것
- 원형 / AABB / OBB Bounding Box 시각화
- 세 방식의 충돌 판정 차이 관찰


## 관찰 내용


### 원형 vs AABB

AABB는 축 기준으로 충돌을 판단하기 때문에, 사각형 모서리까지 닿으면 즉시 충돌이 감지되는 반면
원형은 반지름 기준으로 계산되므로, 대각선으로 접근할 경우 모서리 근처에서 AABB방식보다 조금 늦게 충돌이 감지됩니다.
정리하자면 AABB 방식은 빠르고 민감하지만 모서리에서 과도하게 충돌 감지되고 원형은 약간 늦게 감지되지만 더 오브젝트에 자연스럽게 충돌됩니다.



### AABB vs OBB

AABB는 객체의 경계를 축에 평행하게 정렬하므로, 충돌 감지가 상대적으로 빠르고 직관적입니다.
단, 객체가 회전하면 충돌 감지가 부정확할 수 있습니다. 
회전되는 사각형은 AABB로 감지될 때 크기가 더 커지거나 더 작아지는 문제가 발생할 수 있습니다.
OBB는 회전된 객체를 그대로 반영하여 충돌을 감지하므로, 회전된 객체를 정확히 추적할 수 있습니다. 회전된 상태에서도 더 정밀한 충돌 감지를 제공합니다.


## AI와의 대화에서 배운 것
(흥미로웠던 AI 답변 요약)

AI한테 3가지 충돌방식에 대해 질문하면서 실제 게임에선 어떤 방식의 충돌 방식이 가장 많이 이용되냐고 물어봤더니 흥미로운 답변을 들을 수 있었다.

AI 답변 요약 :
결론부터 말하면 **“하나만 쓰는 게 아니라 상황에 따라 섞어서 쓴다”**가 정답이야.

핵심 결론 (실무 기준)
대부분 게임은 이렇게 사용함:

1단계: AABB (빠른 1차 필터)
2단계: Circle or 간단 충돌
3단계: SAT / 정밀 충돌

왜 여러 개를 섞어 쓰냐?

SAT(OBB)는 정확하지만:

연산 많음 (축 + 투영 반복)
오브젝트 많으면 프레임 드랍

그래서:
 "일단 대충 걸러내고 → 진짜 필요한 것만 정확하게 계산"

한 가지 방식만 이용되는 것이 아닌 일단 가장 단순한 충돌 방식으로 한번 계산량을 줄이고 복잡한 충돌 계산을 진행하는 게 일반적인 게임에 이용되는 방식이라는 걸 알게 되었다.


두 번째로 AI에게 원형 출동 감지에서 math.sqrt 를 쓰는 이유에 대해 질문 하였고 sqrt 없이도 구현할 수 있는지 물어보았더니
실제 게임에선 sqrt를 사용하지 않는 게 정확도도 동일하고 계산이 더 빠르기 때문에 쓰지 않는다는 흥미로운 답변을 얻을 수 있었다.

AI 답변 :
math.sqrt는 “실제 거리”를 구하려고 쓰는 거고,
충돌 판정만 할 거면 없어도 된다 (오히려 더 좋다)

게임 개발에서의 정석
대부분 이렇게 씀:

if dx*dx + dy*dy < r*r:
    collision = True

이유:
sqrt 제거 → 성능 향상
정확도 동일

충돌 판정은 거리 자체가 아니라 ‘거리 비교’만 필요하다



마지막으로 AI에게 3 충돌 방식에 대해 비교 정리 해달라고 질문했더니 3 충돌 방식을 표로 정리해주었다.

AI 답변 : 
세 방식 비교 정리
방식	       정확도	속도	   회전 지원
AABB	        낮음	      매우 빠름	❌
Circle	        중간	        빠름	         ✔
OBB+SAT	매우 높음	느림	         ✔





## 내 게임에 적용한다면
(어떤 방식을 쓸 것인지, 이유는?)

나는 2D 도트 그래픽으로 된 게임을 만들고 싶다. 도트 게임은 움직임이 직선적이고 회전이 적은 경우가 많아 AABB 방식이 적합할 거 같다. AABB방식은 계산이 빠르고 직관적이므로 가장 효율적이다. 
또한, 도트 게임에선 직사각형 형태의 장애물들이 자주 등장하므로 AABB 충돌 방식이 성능과 정확성 사이의 균형을 잘 잡을 수 있을 거 같다.
