# 5주차 실습 기록

## 선택한 템플릿 및 주제

- **템플릿**: space_shooter
- **주제**: 리듬 메커니즘을 결합한 로그라이크 우주 슈팅 게임
- **최종 타이틀**: PULSE DRIVE

### 주제 선정 이유
처음에는 단순한 로그라이크 우주 슈팅 게임을 만들려고 했다. 다른 친구들의 수업 시간에 다른 친구들의 기획들을 살펴보며 내 게임만의 차별화할 요소가 필요하다는 것을 느꼈고, 리듬 게임 요소를 결합하면 "박자에 맞춰 쏠수록 강해진다"는 직관적이면서도 독창적인 메커니즘이 만들어진다는 점에서 이 방향으로 확정했다. 로그라이트 구조를 더하면 매 판마다 다른 빌드를 시도하는 재미까지 생겨서 세 가지 장르(슈팅 + 로그라이트 + 리듬)가 자연스럽게 하나로 묶이는 구조가 됐다.

---

## 사용한 AI 프롬프트 (요약)

### 1. 장르 및 레퍼런스 조사 요청
**프롬프트 요약**: "비행 슈팅 게임 중 요즘 인기 있는 장르나 트렌드 알려줘"

AI가 Vampire Survivors류 Survivors-like 장르를 소개해줬다. 핵심 루프가 "적 처치 → EXP → 레벨업 → 랜덤 3택 업그레이드"로 단순하면서도 중독성이 강하다는 설명을 듣고 이 구조를 기반으로 삼기로 결정했다. 직접 시장 조사를 했다면 시간이 훨씬 걸렸을 부분을 빠르게 파악할 수 있었다.

### 2. 기존 코드 구조 분석 요청
**프롬프트 요약**: "이 코드의 잘된 부분과 문제점을 분석해줘"

교수님이 주신 템플릿 pygame 코드를 붙여넣고 구조 분석을 요청했다. AI가 렌더-로직 분리, 충돌 set 처리, 무적 깜빡임 구현은 잘 됐다고 평가하면서도 main() 함수가 재귀 호출되는 구조(RecursionError 위험), 별 스크롤 미동작, EXP 시스템 부재, 적이 Rect만 사용해서 스프라이트 시스템과 통합이 안 된다는 문제를 짚어줬다.

### 3. 게임 설계 구체화 요청
**프롬프트 요약**: "꼭 넣어야 할 요소와 여유 되면 넣을 요소를 정리해줘"

개발 범위를 잡기 위해 기능 우선순위를 물어봤다. AI가 꼭 넣기 목록(시너지 시스템, 희귀도 등급, 보스 페이즈 전환, 화면 흔들림, 데미지 숫자 팝업)과 여유 되면 목록(기체 선택, 크리티컬 시스템, HP 드롭, 히트스톱, 배경 변화)으로 나눠서 정리해줬다. 이 분류 덕분에 3주라는 제한된 기간 안에 무엇에 집중해야 할지 명확해졌다.

### 4. 기획서 초안 작성 요청
**프롬프트 요약**: "꼭 넣기/여유 되면 목록을 포함해서 기획서를 작성해줘"

14개 챕터로 구성된 GDD 초안(v1.0)을 작성해줬다. 무기 스펙표, 적 스탯표, 보스 데이터, 스폰 주기 테이블, 개발 일정까지 포함된 상당히 구체적인 문서가 만들어졌다. 이후 리듬 시스템을 추가한 v1.4, 제공한 템플릿 양식에 맞춘 최종 v2.0까지 총 3회 반복 수정했다.

### 5. 리듬 시스템 구현 방식 비교 요청
**프롬프트 요약**: "BPM 고정 메트로놈 방식과 BGM 싱크 방식 중 어떤 게 구현이 쉬운지 알려줘"

두 방식의 구현 복잡도를 비교해달라고 요청했다. AI가 BPM 고정 방식은 pygame.time.get_ticks() 하나로 구현 가능하고, BGM 싱크 방식은 오디오 분석 라이브러리(librosa 등)가 필요하고 pygame.mixer의 재생 지연(latency) 문제까지 해결해야 한다고 설명해줬다. 코드 예시도 함께 보여줘서 두 방식의 차이를 직접 확인하고 BPM 고정 방식으로 결정했다.

### 6. BPM 수치 추천 요청
**프롬프트 요약**: "게임 재미, 템포, 난이도를 고려해서 적절한 BPM을 추천해줘"

단순히 숫자만 추천받는 게 아니라 근거를 함께 요청했다. AI가 80~180 BPM 범위를 표로 비교하면서 128 BPM을 추천했다. 비트 간격 0.469초가 슈팅 게임의 긴박감과 잘 맞고, ±80ms 판정 오차가 비트 간격의 약 17%라 연습하면 맞출 수 있지만 무의식적으로는 어렵다는 설명이 설득력 있었다. 보스전에서만 160 BPM으로 올리면 긴장감이 자연스럽게 상승한다는 팁도 유용했다.

### 7. Suno AI 프롬프트 작성 요청
**프롬프트 요약**: "128 BPM 일반 스테이지와 160 BPM 보스전 음악을 Suno AI에 요청할 프롬프트 작성해줘"

직접 Suno AI 프롬프트를 작성하기가 막막해서 요청했다. 장르 태그, 분위기 키워드, 악기 구성까지 포함한 프롬프트와 함께 Suno의 Style 칸에 따로 입력할 짧은 태그 목록도 분리해서 줬다.

### 8. 게임 타이틀 추천 요청
**프롬프트 요약**: "내 게임 특성에 맞는 영문 타이틀 추천해줘" / "한글 타이틀도 추천해줘"

영문과 한글을 각각 따로 요청했다. 영문은 리듬 강조 / 우주+리듬 조합 / 긴박감 강조 세 카테고리로 나눠서 12개를 추천해줬고, 한글은 리듬 강조 / 우주+리듬 / 감각적 표현 등으로 나눠서 16개를 추천해줬다. 각 타이틀마다 어떤 느낌인지 한 줄 설명이 붙어 있어서 비교하기 편했다. 영문+한글 조합("PULSE DRIVE: 공명")도 제안해줬는데 결국 영문 단독 PULSE DRIVE로 확정했다.


## AI 답변에서 도움이 된 것

### BPM 선택의 근거 제공
128 BPM이라는 숫자만 알려준 게 아니라 왜 그 숫자인지를 비트 간격, 판정 오차 비율, EDM 장르 관습까지 연결해서 설명해줬다. 단순히 추천을 따른 게 아니라 근거를 이해하고 직접 판단해서 선택할 수 있었다. 보스전 160 BPM 전환 아이디어도 AI가 제안한 것인데, 상태 전환 때 비트를 리셋하기만 하면 구현도 간단하다는 설명 덕분에 바로 채택했다.

### 구현 방식의 트레이드오프 비교
BPM 고정 vs BGM 싱크 방식 비교에서 단순히 "이게 쉽다"가 아니라 각 방식의 구체적인 구현 난이도와 문제점을 코드 예시와 함께 설명해줬다. 미리 알고 시작한 덕분에 처음부터 올바른 방향으로 설계할 수 있었다.

### 기획 누락 요소 발견
v1.4 기획서를 제출했을 때 AI가 자발적으로 문제점을 짚어줬다. 리듬 비트의 기준이 없다는 것(BPM 고정인지 BGM 싱크인지 명시되지 않음), v1.0에 있던 이중샷 무기가 v1.4에서 사라진 것, 난이도 곡선이 "레벨 기반 증가"라고만 되어 있고 구체적인 수치가 없다는 것을 지적해줬다.

### Suno 프롬프트 실용성
Suno AI를 처음 써보는 입장에서 어떤 키워드를 어떻게 입력해야 원하는 결과가 나오는지 감이 없었다. AI가 본문 프롬프트와 Style 칸을 구분해서 작성해준 덕분에 바로 붙여넣고 사용할 수 있었다.

### 타이틀 카테고리별 비교
타이틀을 단순 나열이 아니라 컨셉별로 묶어서 추천해줬기 때문에 내가 어떤 방향의 이름을 원하는지 생각하면서 고를 수 있었다. 각 타이틀에 한 줄 설명이 붙어 있어서 이름이 어떤 인상을 주는지 비교하기 편했다.

## AI 답변을 수정하거나 버린 것

### 기체 선택 시스템 축소
AI가 초안에서 3종 기체(아레스/팬텀/포지)를 HP, 이동 속도, 시작 무기, 패시브 특성까지 상세히 설계해줬다. 내용 자체는 좋았지만 리듬 시스템이 추가되면서 개발 범위가 이미 충분히 넓어졌다고 판단해서 기체 선택은 "여유 되면" 항목으로 후순위로 밀었다. 3주 개발 기간 안에 모든 걸 구현하려다 아무것도 완성하지 못하는 것보다 핵심 기능을 먼저 완성하는 게 낫다고 생각했다.

### 보스 트리거 방식 변경
AI 초안은 보스가 3분·6분·10분 고정 시간에 등장하는 시간 기반 트리거였다. 그런데 리듬 숙련도에 따라 PERFECT를 많이 치면 데미지가 높아져서 적을 더 빨리 처치하고 레벨업도 빠르게 된다. 결국 플레이어 실력에 따라 레벨업 속도가 달라지므로 시간 기반보다 레벨 기반(Lv.5/10/15)이 게임 흐름과 더 잘 맞는다고 판단해서 직접 수정했다.

### 한글 타이틀 후보 대부분 기각
AI가 추천한 "박자폭격", "리듬사격", "우주박자" 같은 후보들은 게임 내용을 너무 직접적으로 설명하는 느낌이라 제목으로서의 임팩트가 부족하다고 느꼈다. "공명", "파동" 같은 감각적인 후보는 분위기는 좋지만 우주 슈팅 게임이라는 장르가 전혀 연상되지 않는다는 단점이 있었다. 결국 장르와 리듬을 동시에 암시하면서 발음도 깔끔한 영문 타이틀 PULSE DRIVE로 확정했다.

### 시너지 수 축소
AI 초안에는 시너지가 6개(관통 레이저, 폭풍 산탄, 연쇄 폭발, 유도 강화, 저격 모드, 분열 미사일)였다. 그런데 리듬 시스템 전용 시너지(리듬 폭풍)를 새로 추가하면서 전체 균형을 맞추기 위해 기존 시너지 중 저격 모드와 분열 미사일을 제외하고 4개로 줄였다. 시너지가 너무 많으면 플레이어가 조합을 파악하기 어렵고 밸런스 조정도 복잡해지기 때문이다.

### 난이도 설계 방식 전면 재작성
AI 초안의 난이도 설계는 시간 기반 스폰 테이블(0~1분, 1~2분, 2~4분 등)로 작성되어 있었다. 보스 트리거를 레벨 기반으로 바꾸면서 난이도 전체를 레벨 구간 기준으로 다시 설계해야 했다. 단순히 표의 기준을 시간에서 레벨로 바꾸는 게 아니라 레벨업 속도와 적 스폰 주기의 관계를 다시 생각해서 Lv.1~3 / 4~6 / 7~9 / 10~14 / 15+ 구간으로 직접 나누고 각 구간의 특이사항을 새로 작성했다.

### 점수 시스템 신규 추가
v1.0 기획서에는 점수 시스템이 없었다. AI도 초안에서 별도로 제안하지 않았는데, 리듬 시스템을 추가하면서 PERFECT 판정에 점수 보상을 주지 않으면 리듬을 맞출 동기가 데미지 강화뿐이라 약하다는 생각이 들었다. 그래서 적 처치 점수 / 보스 처치 점수 / PERFECT 점수 / 콤보 배율 구조를 직접 설계해서 추가했다. 이 부분은 AI의 도움 없이 게임 디자인 관점에서 직접 판단한 내용이다.
